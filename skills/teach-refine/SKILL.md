# teach-refine — 依回饋更新 TA（讓 agent 越做越好）

**觸發**：`用「teach-refine」這個 skill，TA 資料夾：____，回饋來源：____。`
（回饋來源可為：老師試用意見、學生問答紀錄、`ACCEPTANCE-CHECKLIST.md` 的失敗項——任一或多個。）

> **核心規則：回饋撐不起的修改不做；老師確認前不動任何檔。**
> teach-agent 負責「生出 TA」，本 skill 負責「上線後的每一輪變好」——兩者合成閉環。
> 底線規則見 `../../constitution.md`。

## 1. 收斂回饋為逐條可裁決項

讀完全部回饋來源後，整理成一張表，每條一列：

| # | 回饋原文（摘） | 對應層 | 建議動作 | 狀態 |
|---|----------------|--------|----------|------|

**對應層固定四種**（一條回饋恰標一層；跨層就拆成多條）：

1. **AGENT.md 行為規則**——語氣、範圍、該做不該做（例：「作業題講太多」→ 提示的止損線）。
2. **某週蒸餾檔**（`lecture-notes/`）——內容錯漏、深度不對、例子不貼。
3. **知識圖譜／先備**（`knowledge-graph.md`、`prerequisites.md`）——先備關係缺漏或錯置。
4. **某 skill 本身**——重複性任務的做法要改（規則、格式、流程）。

- **判不出層或太模糊的回饋**：標「待老師釐清」，不猜、不動檔。

## 2. 修正案先行（老師確認後才動手）

對每條「可裁決」項，寫出修正案：**要改什麼、為什麼、影響哪些檔**（一句一項即可）。
整表交老師確認——**得到確認前，本 skill 不修改任何檔案**。

## 3. 最小修改（一次一層）

- 只改確認過的條目；**一輪只動一層**（多層需求分多輪），不順手重寫其他內容。
- 行為規則衝突時以 `AGENT.md` 為準；**改 AGENT.md 本身必須有老師確認紀錄**。

## 4. 重跑相關驗收探針

- 只重跑 `ACCEPTANCE-CHECKLIST.md` 中**與本輪修改層相關**的探針
  （改行為規則→跑 Tier 1 誠信探針；改蒸餾→跑該週正確性抽問；改圖譜→跑先備引導；改 skill→跑該 skill 的產出驗收）。
- 探針沒過就回步驟 2 修訂修正案，不硬標完成。

## 5. REFINE-LOG.md 留痕（一輪一節）

在 TA 資料夾根層維護 `REFINE-LOG.md`，每輪附加一節：

```markdown
## <日期> 第 N 輪
- 回饋來源：____
- 裁決表：（貼步驟 1 的表，含「待老師釐清」項）
- 修改：<檔案> — <一句話>（每檔一行）
- 驗證：重跑探針 <清單> — 結果 <過／不過>
```

## 6. 輪末一致性檢查

每輪結束固定核對（任一不符就修到符）：

- [ ] 技能清單：`skills/` 實際資料夾 ↔ README 技能表 ↔ USER-MANUAL 章節，一致。
- [ ] 觸發句：各 SKILL.md 的觸發句與文件引用處逐字一致。
- [ ] TA 端文件：`INSTRUCTOR-MANUAL.md`／學生版 README 的描述未因本輪修改而過期。

## 驗收（老師逐項打勾）

- [ ] 每條回饋恰有一個裁決（含「待老師釐清」）；無未經確認的檔案修改。
- [ ] 本輪只動了確認過的層；AGENT.md 修改附確認紀錄。
- [ ] 相關驗收探針重跑且通過；REFINE-LOG.md 新增一節、四欄齊備。
- [ ] 輪末一致性檢查三項全過。
