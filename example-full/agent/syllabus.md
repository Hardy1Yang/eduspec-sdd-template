## 先備要求（Prerequisite）
- 修過以微積分為基礎的統計課程（a calculus-based statistics course）
- 具備以 R、Python 或 Stata 進行資料處理的經驗
- 課程不限制使用的程式語言；但**作業解答與課堂示範以 R 為主**

## 課程定位
課程介紹資料科學的兩種視角：
- **狹義**：用模型找出資料中的規律，執行四大核心任務——預測（prediction）、推論（inference）、分群（segmentation）、反事實分析（counterfactual analysis）
- **廣義**：以科學思維（假說驅動的推理、量化、實證）解決真實世界問題、支援決策——這是期末專案的重點

## 課程格式
- 課內：前兩小時理論講授，第三小時為個案討論（case study）、工作坊或專案討論
- 課外：五份個人作業 + 分組期末專案（以海報發表收尾）
- 每個 case 附案例描述與三組引導問題，並提供 RMarkdown 完整參考解答；作業含 case 的延伸題（extension question），各組會被指派一題並於課堂上發表

## 四大模組（Course Content）
1. **預測（Prediction）**：決策樹、隨機森林、交叉驗證；案例：販賣機選址與裝設攝影機的決策
2. **因果推論（Causal Inference）**：潛在結果架構、隨機對照試驗（RCT）、檢定力分析、honest trees、causal forests；案例：發放折價券是否提升使用者忠誠度
3. **分群（Clustering）**：主成分分析（PCA）、階層式分群、k-means、高斯混合模型；案例：依使用者輪廓設計個人化行銷
4. **反事實分析（Counterfactual Analysis）**：多項羅吉特（multinomial logit）、BLP 方法；案例待定（時間可能非常有限，多以案例與程式碼走過一遍作為 preview）

## 期末專案（Final Project）——課務與管理規範

> 整合 Syllabus「Final Project」與〈(ECON5166) 期末專案的管理與交付規範〉。此管理規範**僅適用於期末專案**；Case Study Presentation 無需套用。**專案內容指導不屬本助教範圍**（另有專案 repo），本節僅供課務查詢。

### 專案目標
- 分組實作，將課堂工具與原則應用到真實問題
- 題目應是「源自日常生活的實證研究問題」，例如：
  - 「北部與南部台灣對政治人物的偏好是否不同？」
  - 「哪些因素影響捷運需求？」
  - 「如何偵測 PTT 上的協同性假訊息操作？」
- **不鼓勵純工程導向的專案**（如 Kaggle 式競賽）；可以包含建模成分（如預測演算法），但必須服務一個更大的問題
- 週次 15 舉辦海報發表會（類似高中科展）：準備海報、5–7 分鐘發表、並給其他組建設性回饋（週次以最新公告為準）

### 交付物（依管理規範前言）
1. 研究提案：確認成員、研究題目與資料需求
2. 期中報告（第一次）：報告資料相關的文件
3. 期中報告（第二次）：報告初步分析結果
4. 期末演練：海報草稿、試講影片與逐字稿
5. 期末海報展：海報、報告與提供其他組別回饋
6. GitHub Repository

### 管理規範（為什麼要這樣做）
- 課程提供 GitHub Repository template 與管理規範，目的：讓合作更順暢、統一 presentation 格式、便於事後追蹤成員個別貢獻
- 使用 git 版控；GitHub 上的檔案直接作為課堂口頭報告（proposal & progress presentation）與個人評分調整的基礎——進度報告**不需要額外做投影片**，直接展示依規範撰寫的筆記本
- 各任務類型（清理資料、迴歸分析等）的交付內容有規範；工作時請使用課程提供的範本筆記本，確保交付內容符合規範
- 版控與文件確保結果可重製；統一資料夾結構降低溝通成本
- 學這套流程需要適應成本，但能在無形中學會專案管理概念，對未來學術或業界都有幫助

### Repo 資料夾結構（第一層，必須遵守）
- `data/`：原始資料、處理過的資料與程式碼
- `finding/`：與資料分析有關的工作，以筆記本呈現，含程式碼、圖表與模型估計結果
- `report/`：研究提案與期末海報
- `note-template/`：各類文件與程式碼的範本（**此資料夾內容請勿更動**）

### 檔案命名與程式碼註解
- 檔名一律小寫、不要有空格、用 dash (-) 取代
- 用有明確意義的文字命名，避免 final、new、test 等模糊詞彙
- 寫程式請善用 copilot 等 AI 工具，並對每段程式碼提供註解

### GitHub Repo 與本地工作資料夾
- Repo 存放兩處：GitHub repo（只上傳程式碼和文件）；本地端資料夾（所有檔案）
- **Commit 納入程式碼與文件，但不要放任何資料檔**
- 資料與外部檔案（如 Google Doc）本身不進 repo，但要在資料夾內建立對應文件並 commit：
  - 資料更新：產生資料的程式碼與資料描述文件要被 git 紀錄
  - 雲端檔案：在資料夾內建立同名 .md file，用 git 紀錄工作進度

### 驗收與交付規範
- 第七週與第十週的期中報告、以及團體報告的個人分數調整，**以 GitHub 上的內容為依據**；不在 GitHub 上的檔案不列入評分範圍（週次以最新公告為準）
- 撰寫程式碼與文件時使用 template repo 提供的範本；各資料夾該出現的檔案在 `note-template/` 都有對應範本，除非有特殊原因請使用範本
- 第一次期中報告：完成資料蒐集與清理、可準備進入分析階段；展示 `/data/processed` 裡的筆記本，說明資料內容與敘述統計結果
- 第二次期中報告：應有兩、三份統計分析結果可以分享；展示 `/findings` 裡的筆記本，說明初步分析結果
