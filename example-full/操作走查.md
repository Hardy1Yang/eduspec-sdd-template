# 操作走查 — 從原始課程檔案到助教＋整套教材（實測紀錄）

> 目的：在乾淨目錄中，只依套件自身文件（GETTING-STARTED、各 skill 的 SKILL.md）重現「rawcourse → 助教 → 全部教材 → SDD」全流程，驗證可重現性。
> 測試者角色：一位「照文件做」的老師。所有生成內容為繁體中文台灣用語。
> 本紀錄**不含任何作業／考試解答**，僅記錄操作指令與流程互動。
>
> **兼作 example 指南**：把 `<lecture-notes>`／`<supp>` 換成你自己的講義與補充素材路徑、`w2-prediction` 換成你的單元名，照 Step 0→8 走一遍，就是「從原始檔案到助教＋整套教材」的完整範例。對 coding agent 說的觸發句（`用「teach-○○」這個 skill，…`）就是介面本身。
>
> **標記說明**：👤＝**人工執行**（老師在終端機打指令、對 agent 說觸發句、或審核確認）；🤖＝**agent 自動執行**（coding agent 照 SKILL.md 自己做，人不用動手）。整個流程的模式是：**👤 一句話 → 🤖 全部做完 → 👤 審核打勾**。

## Codex 路線（同一流程、真機 codex-cli 實測通過）

用 **Codex** 的老師照同樣 Step 0→8 走，差異只有三點（2026-07-11 以 codex-cli 0.142.5 全程實測，9 次呼叫全數一次成功）：

1. **呼叫方式**：互動模式直接開 Codex 對話說觸發句；批次模式用
   `codex exec --sandbox workspace-write '用「teach-○○」這個 skill（skills/teach-○○/SKILL.md），…'`
   ——批次模式**不能中途等人**，SKILL 的「請老師確認再往下」需在指令內預授權（例：「迷你規格自審後直接繼續」），事後再人工審產物。
2. **PDF 講義**：Codex 沒有內建 PDF 讀取，先裝 poppler（`brew install poppler`），Codex 會自行用 `pdftotext` 轉檔（實測它會先 `command -v` 確認再用）。
3. **問助教**：`codex exec --sandbox read-only 'Use $<課程代碼>-ta-agent to answer: 你的問題'`（互動模式同句）。

實測結果摘要：蒸餾 8/8 分類、零解答外洩；建 agent 零殘留佔位；三教材簽名規則全過（quiz 計算獨立驗算全對）；teach-sim 走完整 spectra SDD（validate/task done/archive 全 exit 0，OLS 數學與獨立計算十位小數一致）；動畫真渲染 19 秒 mp4；助教四探針全過（作業題守「一步為限」）。各步單呼叫 4–12 分鐘。
