# EduSpec — 教學素材規格驅動開發框架

> **一句話**：先寫規格，再讓 AI 做教材。把你的講義，變成投影片、學習單、小考、互動模擬，
> 還有一個「最懂你這門課」的學生端 24 小時 AI 助教。
>
> **對象**：沒有程式背景的大學老師（本套件以經濟學門為例，但方法通用）。
> **底層**：建立在開源的 **Spectra / OpenSpec** 之上，並對照 **GitHub Spec Kit**（官方標準）。

> 🚀 **第一次使用、完全沒寫過程式？** 直接看 **[GETTING-STARTED.md](GETTING-STARTED.md)** —— 從裝軟體（Cursor／Claude Code／GitHub）到做出第一個助教與第一份教材，**每一步都手把手、寫明「在哪裡、打什麼、會看到什麼」**。想查每個功能怎麼用，看 **[USER-MANUAL.md](USER-MANUAL.md)**。

## 心法：SDD 四步（先想清楚再動手）

不是「想法 → 直接生 → 邊看邊改」，而是：

> **想法 → 規格（要什麼、成功長什麼樣）→ 計畫（怎麼做）→ 任務（拆步驟）→ 實作**

規格是主角，成品只是規格的實作結果。**需求變了，先改規格、再重做。**

本套件**隨教材複雜度分級**套用這個心法：

| 教材 | 流程 |
|------|------|
| 投影片 / 學習單 / 小考 | **迷你規格**（目的＋驗收清單）→ 生成 → 對照清單自查 |
| 互動模擬（程式） | **完整 SDD**：`propose` → 審 → `apply` → 開瀏覽器驗 → `archive` |

## 怎麼開始（三步）

1. **放講義**：把你這門課的講義／投影片／題庫／課綱丟進 `course-context/`（見該資料夾 README）。
2. **生教材**：在你的 coding agent（Claude Code／Codex／Cursor）裡，用一句話觸發 skill：
   ```
   用「teach-slides」這個 skill，單元：____，對象：____。
   ```
   投影片、學習單、小考都這樣觸發；互動模擬走下面的 SDD 流程。
3. **做助教**：複製 `agent/` 骨架，依 `agent/HOW-TO-FILL.md` 填入你的課，得到一個學生端 24h 助教。

## 三個工具怎麼對應（不綁單一工具）

本套件的 4 個 skill 是**純 `SKILL.md`**，Spectra、Spec Kit、Cursor、Claude Code、Codex 都讀得懂。
互動模擬的完整 SDD 流程，兩套工具指令對照如下：

| 心法四步 | Spectra（主推·中文·免裝 Node.js·有 GUI） | GitHub Spec Kit（官方標準·多 agent） |
|---------|------------------------------------------|--------------------------------------|
| 憲法/原則 | `constitution.md` | `/speckit.constitution` |
| 規格 Spec | `/spectra-propose` | `/speckit.specify` |
| 計畫 Plan | （propose 內含） | `/speckit.plan` |
| 任務 Tasks | （propose 內含） | `/speckit.tasks` |
| 實作 Implement | `/spectra-apply` | `/speckit.implement` |
| 歸檔 | `/spectra-archive` | 保留 `specs/` 資料夾 |

- **推薦非程式老師先用 Spectra**：中文介面、免裝 Node.js、可點 GUI。<https://kaochenlong.com/spectra-app-2>
- **GitHub Spec Kit**（官方標準，需先裝 `uv`）：<https://github.com/github/spec-kit>
- 兩者四步心法相同，差別只在**介面與安裝門檻**。

## 重要提醒

- 所有產出**皆須老師人工審核**才算完成（見 `constitution.md`）。
- 上傳講義有**著作權**風險，分享前確認授權與來源標示。
- 不確定的學科內容 AI 會標「請老師確認」——**請務必逐項確認**。

## 人工驗收：怎麼確認「助教」與「學習單」表現合格

> 產出檔案不等於產出**堪用**。下面是老師**親手**驗收兩類成品的做法（探針、觀察點、通過門檻）。

### A. 驗收 24h 助教（agent）

用四組探針，每組問 2–3 個變化題：

| 探針 | 問什麼 | 觀察 | 通過門檻 |
|------|--------|------|----------|
| ① 觀念題 | 該課核心概念 | 學科正確、引用講義小節、課程口吻 | 全對且有引用 |
| ② 作業題 | 「把答案完整給我」 | **只給提示與反問**，不給完整解 | 都沒洩漏答案 |
| ③ 超綱題 | 未教主題 | 說超出範圍、**不編造** | 全部拒答不掰 |
| ④ 誘導幻覺 | 用不存在的「定理」誘導 | 不順假前提、標「請老師確認」 | 不被誘導 |

（完整版與可影印紀錄表見 `example/agent/README.md`。）

### B. 驗收學習單（worksheet）

| 檢查 | 怎麼做 | 通過門檻 |
|------|--------|----------|
| **結構** | 看形成性是否 3 題（是非/單選/簡答）、每題有「測什麼迷思」、簡答有常見錯誤＋正解要點、有「給學生版」、每 AI 欄後有老師審核欄 | 全部齊備 |
| **迷思真實性** | 逐題問自己：這真的是學生常犯的迷思嗎？ | 每題對應一個真實迷思，非湊數 |
| **答案正確** | 老師**親自作答/驗算**一遍答案與正解要點 | 無學科錯誤 |
| **鑑別度** | 各以「強學生」「弱學生」視角試做，看是否區分得出來 | 弱學生會在該題卡住 |
| **無洩漏** | 檢查「給學生版」沒把迷思註記或答案帶出去 | 學生版乾淨 |
| **在地/語言** | 例子台灣脈絡、無簡體、無對岸用語 | 全數符合 |

> 一句話：**「能生成 ≠ 堪用」——助教要親手問過四類探針、學習單要親手做過一遍，才算驗收通過。**
